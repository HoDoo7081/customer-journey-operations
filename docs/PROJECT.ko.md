# 유료 프리랜서 프로젝트 — 코칭 서비스 운영 워크플로

실제 고객의 의뢰를 받아 구축하고 운영 환경에 배포한 유료 프리랜서 프로젝트다. 이 저장소는 납품 소스에서 운영 계정과 개인정보를 제외해 정리한 공개본이다.

## 문제와 목표

코칭 서비스의 신청, 결제 확인, 날짜 선택, 예약 확정, 안내 이메일과 운영 기록이 서로 연결되어야 했다. 결제하지 않은 신청자가 코칭 시간을 선점하면 실제 결제 고객의 선택지가 줄어들고, 운영자가 상태를 수동으로 맞추는 과정에서 누락과 중복이 생길 수 있었다.

핵심은 홈페이지 자체보다 **고객과 운영자가 다음에 해야 할 일을 명확하게 만드는 운영 흐름**이었다.

## 설계한 운영 방식

1. 고객이 신청 정보를 입력한다. 이때 캘린더는 점유하지 않는다.
2. 신청 후 12시간 내 외부 결제를 안내한다.
3. 운영자가 실제 결제 내역을 확인하고 관리자에서 확인 작업을 실행한다.
4. 고객에게 본인 전용 날짜 선택 링크가 자동 이메일로 발송된다.
5. 고객이 가능한 일정을 선택하면 캘린더와 예약 상태를 확정한다.
6. 확인 기한이 지난 신청은 만료하되, 실제 결제가 확인되면 운영자가 복구할 수 있다.

운영 기준은 주말 포함 매일 09–23시, 종료 시각 기준, 최소 24시간 전, 향후 30일, 코칭 간 준비시간 10분이다. 관리자에서 강사별 운영시간과 차단 시간을 수정할 수 있다.

## 출시 후 개선 사례

- 중복 신청과 저장 장애를 같은 오류로 보여주던 문제를 구분하고, 기존 신청 안내를 명확하게 했다.
- 관리자에서 신청 답변, 결제·예약·메일 상태를 함께 볼 수 있도록 개선했다.
- 운영자가 테스트 신청을 삭제할 때 이메일 재입력과 명시적인 확인을 요구하도록 했다.
- 테스트 삭제는 관련 캘린더 예약을 해제하고 Notion 기록을 보관 처리한다. 원본과 감사 이력은 유지하고, 일부 실패 시 재시도할 수 있게 했다.
- 메일 발송 결과가 불확실할 때 무조건 재발송하지 않고 검토 상태로 두어 중복 안내 위험을 줄였다.

## 검증과 결과의 범위

실제 운영 환경에서 운영자 테스트 데이터를 이용하여 신청·예약·알림·정리 흐름을 검증했다. 테스트 삭제 검증 시 기존 신청 6건과 이벤트·운영 정책이 보존됨을 확인했다. 이 숫자는 검증 시점의 보존 대조 기준이며 서비스 규모나 사업 성과 지표가 아니다.

이 공개본은 운영 식별자와 연락처, 고객 데이터, 첨부문서, 인증정보를 제외한 별도 스냅샷이다. 여기서 실행하는 자동 테스트는 모의 제공자를 사용하는 회귀 테스트이며 실제 연동 검증과 구분한다.

## 다른 업무로 확장 가능한 역량

요구사항을 상태·권한·예외 규칙으로 구체화하고, 여러 도구의 데이터를 연결하며, UAT와 운영자 안내를 거쳐 출시 후 문제를 개선한 경험이다. 구축 컨설팅, Managed Services, Customer Success, 솔루션 컨설팅에 적용할 수 있다.

AI 코딩 도구를 활용한 프로젝트다. 지원자가 설명할 핵심은 직접 결정·검토한 요구사항과 운영 판단, 검증 과정이며, 실제 역할보다 넓은 단독 개발·리더십 범위나 측정하지 않은 성과를 주장하지 않는다.
